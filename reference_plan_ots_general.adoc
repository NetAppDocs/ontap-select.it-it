[[required-windows-knowledge-and-skills-for-hyper-v]]
== Conoscenze e competenze di Windows richieste per Hyper-V

Windows Server con l'hypervisor Hyper-V è un ambiente complesso. Prima di implementare ONTAP Select su Hyper-V, devi avere le conoscenze e le competenze necessarie.

L'utilità di amministrazione ONTAP Select Deploy crea e gestisce la macchina virtuale (VM) ONTAP Select. Ti servono le seguenti competenze per preparare l'host Windows amministrato da Deploy e verificare che l'host soddisfi i requisiti di ONTAP Select.

Amministrazione di Windows Server:: Dovresti avere esperienza con la release di Windows Server per la tua distribuzione ONTAP Select. In particolare, dovresti essere in grado di eseguire le seguenti attività:
+
--
* Installa e aggiorna Windows Server
* Identifica la release di Windows Server installata e verifica che sia supportata
* Installare e abilitare i ruoli del server e le funzionalità opzionali, incluso il ruolo Hyper-V
* Configurare il sistema utilizzando l'interfaccia CLI
* Dimensiona la CPU host e la memoria in modo che rimanga capacità disponibile sull'host dopo la distribuzione di un nodo ONTAP Select


Per ulteriori informazioni su come preparare il tuo server Windows, incluse la configurazione e i pacchetti software necessari, consulta link:hyper-v-host-configuration-and-preparation-checklist.html["lista di controllo della configurazione host"].

--
Concetti e amministrazione di Hyper-V:: Dovresti avere familiarità con i concetti generali di virtualizzazione e con la piattaforma Hyper-V. In particolare, dovresti comprendere quanto segue:
+
--
* Come l'attivazione del ruolo Hyper-V modifica la rete e lo storage sull'host
* Come Hyper-V presenta lo storage a una macchina virtuale, inclusa la differenza tra un disco rigido virtuale e un disco fisico che viene passato a una macchina virtuale
* Come visualizzare la configurazione e lo stato di una VM e delle sue risorse



NOTE: L'utilità di amministrazione Deploy crea e gestisce la VM ONTAP Select. Non riconfigurare, creare checkpoint, migrare o eliminare la VM utilizzando Hyper-V Manager, Failover Cluster Manager o PowerShell.

--
Configurazione di rete e switch virtuale:: Dovresti avere familiarità con i concetti di rete e la configurazione degli switch di rete. Inoltre, dovresti essere in grado di eseguire le seguenti attività sull'host Hyper-V:
+
--
* Pianifica e crea switch virtuali esterni e comprendi come ogni switch virtuale è associato a una scheda di rete fisica
* Verifica lo stato del collegamento, la velocità e la configurazione IP delle schede di rete host
* Configura l'assegnazione di tag VLAN in modo coerente sia sull'host che sulla rete fisica
* Configura i frame jumbo su una scheda di rete fisica e determina l'unità di trasmissione massima (MTU) risultante


L'utility di amministrazione Deploy utilizza gli switch virtuali già presenti sull'host, quindi devi pianificare la configurazione degli switch virtuali prima della distribuzione. Ad esempio, un cluster a due nodi richiede una rete interna con un MTU compreso tra 7500 e 9000 byte.

--
Gestione dello storage:: Dovresti essere in grado di gestire dischi e volumi su Windows Server. Nello specifico, dovresti essere in grado di eseguire le seguenti attività:
+
--
* Crea e dimensiona volumi NTFS o ReFS e assegna loro lettere di unità
* Identifica il tipo di supporto, il protocollo di trasporto dello storage (tipo di bus) e la capacità di un disco fisico
* Distingui un disco raw da un disco partizionato o che contiene già un volume
* Inizializza un disco raw da usare nel sistema


--




[[required-linux-knowledge-and-skills-for-kvm]]
== Conoscenze e competenze Linux necessarie per KVM

Linux con l'hypervisor KVM è un ambiente complesso in cui lavorare. Prima di implementare ONTAP Select su KVM, è necessario disporre delle conoscenze e delle competenze necessarie.

Distribuzione server Linux:: Si dovrebbe avere esperienza con la distribuzione Linux specifica da utilizzare per la distribuzione ONTAP Select. In particolare, dovrebbe essere possibile eseguire le seguenti attività:
+
--
* Installare la distribuzione Linux
* Configurare il sistema utilizzando l'interfaccia CLI
* Aggiungere i pacchetti software e le eventuali dipendenze


--


Per ulteriori informazioni sulla preparazione del server Linux, inclusa la configurazione richiesta e i pacchetti software, fare riferimento a link:kvm-host-configuration-and-preparation-checklist.html["lista di controllo della configurazione host"].

Implementazione e amministrazione di KVM:: È necessario acquisire familiarità con i concetti generali di virtualizzazione. Inoltre, ci sono diversi comandi CLI di Linux che è necessario utilizzare come parte dell'installazione e dell'amministrazione di ONTAP Select in un ambiente KVM:
+
--
* `virt-install`
* `virsh`
* `lsblk`
* `lvs`
* `vgs`
* `pvs`


--
Configurazione di rete e Open vSwitch:: È necessario conoscere i concetti di rete e la configurazione degli switch di rete. Inoltre, dovrebbe avere esperienza con Open vSwitch. È necessario utilizzare i seguenti comandi di rete per configurare la rete ONTAP Select in un ambiente KVM:
+
--
* `ovs-vsctl`
* `ip`
* `ip link`
* `systemctl`


--




[[cluster-size-and-related-considerations]]
== Dimensione del cluster e considerazioni correlate

Esistono diversi problemi di pianificazione relativi alle dimensioni del cluster che è necessario prendere in considerazione.

Numero di nodi nel cluster:: Un cluster ONTAP Select è composto da uno, due, quattro, sei, otto, dieci o dodici nodi. È necessario determinare la dimensione del cluster in base ai requisiti dell'applicazione. Ad esempio, se è necessaria la funzionalità HA per un'implementazione aziendale, è consigliabile utilizzare un cluster multi-nodo.
Dedicato e collocato:: In base al tipo di applicazione, è necessario determinare se l'implementazione segue il modello dedicato o collocato. Si noti che il modello collocato può essere più complesso a causa della diversità dei carichi di lavoro e di una maggiore integrazione.




[[hypervisor-host-considerations]]
== Considerazioni sull'host degli hypervisor

Esistono diversi problemi di pianificazione relativi all'host dell'hypervisor che è necessario considerare.


CAUTION: Non dovresti modificare direttamente la configurazione di una VM ONTAP Select, a meno che il supporto NetApp non ti indichi di farlo. Una VM dovrebbe essere configurata e modificata solo tramite l'utility di amministrazione Deploy. Apportare modifiche a una VM ONTAP Select al di fuori dell'utility Deploy senza l'assistenza del supporto NetApp può causare il guasto della VM e renderla inutilizzabile.

Indipendente dall'hypervisor:: Sia ONTAP Select che l'utility di amministrazione di ONTAP Select Deploy sono indipendenti dall'hypervisor. I seguenti hypervisor sono supportati per entrambi.
+
--
* Microsoft Hyper-V
+

NOTE: A partire da ONTAP Select 9.20.1, ONTAP Select supporta l'hypervisor Microsoft Hyper-V.

* Macchina virtuale basata su kernel (KVM)
+

NOTE: A partire da ONTAP Select 9.14.1, il supporto per l'hypervisor KVM è stato ripristinato. In precedenza, il supporto per l'implementazione di un nuovo cluster su un hypervisor KVM è stato rimosso in ONTAP Select 9.10.1 e il supporto per la gestione di cluster e host KVM esistenti, ad eccezione di quelli da mettere offline o eliminare, è stato rimosso in ONTAP Select 9.11.1.

* VMware ESXi


--


Fare riferimento alle informazioni di pianificazione specifiche dell'hypervisor e link:reference_release_notes.html["note di rilascio"] per ulteriori dettagli sulle piattaforme supportate.

Hypervisor per nodi ONTAP Select e utility di amministrazione:: Sia l'utility di amministrazione Deploy sia i nodi ONTAP Select vengono eseguiti come VM. L'hypervisor che scegli per l'utility Deploy è indipendente dall'hypervisor che scegli per i nodi ONTAP Select. Hai la massima flessibilità nell'abbinare i due:
+
--
* L'utility di distribuzione in esecuzione su VMware ESXi può creare e gestire cluster ONTAP Select su VMware ESXi, Hyper-V o KVM
* L'utility di distribuzione in esecuzione su Hyper-V può creare e gestire cluster ONTAP Select su VMware ESXi, Hyper-V o KVM
* L'utilità Deploy in esecuzione su KVM può creare e gestire cluster ONTAP Select su VMware ESXi, Hyper-V o KVM


--
Una o più istanze del nodo ONTAP Select per host:: Ogni nodo ONTAP Select viene eseguito come una VM dedicata. Puoi creare più nodi sullo stesso host hypervisor, con le seguenti limitazioni:
+
--
* Non è possibile eseguire più nodi da un singolo cluster ONTAP Select sullo stesso host. Tutti i nodi di un host specifico devono provenire da diversi cluster ONTAP Select.
* È necessario utilizzare uno storage esterno.
* Se si utilizza il software RAID, è possibile implementare un solo nodo ONTAP Select sull'host.


--
Coerenza dell'hypervisor per i nodi all'interno di un cluster:: Tutti gli host all'interno di un cluster ONTAP Select devono essere eseguiti con la stessa versione e release del software dell'hypervisor.
Numero di porte fisiche su ciascun host:: È necessario configurare ciascun host in modo che utilizzi una, due o quattro porte fisiche. Anche se si dispone di una certa flessibilità nella configurazione delle porte di rete, attenersi alle seguenti raccomandazioni, se possibile:
+
--
* Un host in un cluster a nodo singolo deve avere due porte fisiche.
* Ciascun host di un cluster a più nodi deve disporre di quattro porte fisiche


--
Integrazione di ONTAP Select con un cluster basato su hardware ONTAP:: Non è possibile aggiungere un nodo ONTAP Select direttamente a un cluster basato su hardware ONTAP. Tuttavia, è possibile stabilire una relazione di peering del cluster tra un cluster ONTAP Select e un cluster ONTAP basato su hardware.




[[storage-considerations]]
== Considerazioni sullo storage

È necessario considerare diversi problemi di pianificazione relativi allo storage host.

Tipo RAID:: Quando si utilizza lo storage DAS (Direct-Attached Storage) su ESXi, è necessario decidere se utilizzare un controller RAID hardware locale o la funzionalità RAID software inclusa in ONTAP Select. Se si utilizza il software RAID, vedere link:reference_plan_ots_storage.html["Considerazioni su storage e RAID"] per ulteriori informazioni.
Storage locale:: Quando si utilizza lo storage locale gestito da un controller RAID, è necessario decidere quanto segue:
+
--
* Se utilizzare uno o più gruppi RAID
* Se utilizzare una o più LUN


--
Storage esterno:: Quando si utilizza la soluzione ONTAP Select vNAS, è necessario decidere dove si trovano gli archivi dati remoti e come accedervi. ONTAP Select vNAS supporta le seguenti configurazioni:
+
--
* VMware vSAN
* Storage array esterno generico


--
Stima dello storage necessario:: È necessario determinare la quantità di storage necessaria per i nodi ONTAP Select. Queste informazioni sono necessarie per l'acquisizione delle licenze acquistate con capacità di storage. Per ulteriori informazioni, fare riferimento alla sezione limitazioni della capacità dello storage.



NOTE: La capacità di storage di ONTAP Select corrisponde alla dimensione totale consentita dei dischi dati collegati alla VM ONTAP Select.

Modello di licensing per l'implementazione in produzione:: Devi selezionare il modello di licenza per Tier di capacità o pool di capacità per ogni cluster ONTAP Select distribuito in un ambiente di produzione. Per ulteriori informazioni, consultare la sezione _licenza_.




[[authentication-using-the-credential-store]]
== Autenticazione mediante l'archivio delle credenziali

L'archivio delle credenziali di ONTAP Select Deploy è un database che contiene le informazioni sugli account. Deploy utilizza le credenziali degli account per eseguire l'autenticazione dell'host durante la creazione e la gestione del cluster. Dovresti sapere come viene utilizzato l'archivio delle credenziali durante la pianificazione di un'implementazione di ONTAP Select.


NOTE: Le informazioni dell'account vengono memorizzate in modo sicuro nel database utilizzando l'algoritmo di crittografia Advanced Encryption Standard (AES) e l'algoritmo di hashing SHA-256.

Tipi di credenziali:: Sono supportati i seguenti tipi di credenziali:
+
--
* host
+
Le credenziali *host* vengono utilizzate per autenticare un host hypervisor durante la distribuzione di un nodo ONTAP Select direttamente su ESXi, Hyper-V o KVM.

* vcenter
+
La credenziale *vcenter* viene utilizzata per autenticare un server vCenter come parte della distribuzione di un nodo ONTAP Select in ESXi quando l'host è gestito da VMware vCenter.



--
Accesso:: L'accesso all'archivio delle credenziali viene eseguito internamente durante l'esecuzione delle normali attività amministrative mediante l'implementazione, ad esempio l'aggiunta di un host hypervisor. È inoltre possibile gestire l'archivio di credenziali direttamente tramite l'interfaccia utente Web di implementazione e la CLI.
